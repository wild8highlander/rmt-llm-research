<p align="center">

Standalone research programs built on top of the core package. Each
folder is self-contained: it does not modify the `src/rmt_llm/` core
and ships its own scripts, data, and model artifacts — a research
program can be deleted without touching anything else, or copied out of
the repository and still work. This isolation is deliberate: research
programs are allowed to fail, be rewritten, or branch into A/B studies
without ever destabilizing the verified core library that the rest of
the repository depends on.

## Principles of a standalone program

| Principle | What it means in practice |
|---|---|
| No core edits | the program *imports* the core, never patches it; a bug found in the core is fixed in the core by a separate change |
| Own artifacts | corpora, weights, reports live inside the program folder; weights are gitignored, reports are committed |
| Determinism | fixed seeds everywhere; re-running a stage reproduces the same artifacts bit-for-bit |
| Honest reporting | every headline number links to a generated report (JSON → MD), not to a claim |

## Programs

| Folder | Content |
|---|---|
| [`tinygpt_formula/`](tinygpt_formula/README.md) | **TinyGPT v3 Formula-Edition** — train the repository's NumPy-only transformer on the project's own formulas, evaluate held-out generalization, run the RMT diagnostics, and answer the ROADMAP open questions empirically. Includes the parameter-scaling A/B study (`formula` vs `control` corpus) that measures how true formula content affects confident hallucinations |

Inside the folder, five stages form the pipeline:
[`scripts/`](tinygpt_formula/scripts/README.md) →
[`data/`](tinygpt_formula/data/README.md) →
[`model/`](tinygpt_formula/model/README.md) →
[`scaling/`](tinygpt_formula/scaling/README.md), with
[`colab/`](tinygpt_formula/colab/README.md) as the free-GPU variant.

The stages are strictly ordered: the corpus is built first and hashed,
training consumes the corpus and writes weights + history, evaluation
consumes the weights and produces held-out scores, and the scaling study
wraps the same two stages in a ladder loop. Nothing reads backwards, so
any artifact can be regenerated by replaying only the stages upstream of
it.

## How to use this folder

Start with [`tinygpt_formula/README.md`](tinygpt_formula/README.md) —
the full pipeline reproduces in ~20 minutes on CPU. Two typical entry
points:

- **Reproduce everything locally**: run the five scripts in order from
  the repository root (commands are listed in the program README and in
  [`scripts/`](tinygpt_formula/scripts/README.md)); on a phone, follow
  `scaling/TERMUX_PROOT_UBUNTU.md`.
- **Scale beyond S**: take the notebooks in [`colab/`](tinygpt_formula/colab/README.md)
  to run the M/L/XL rungs of the ladder on free GPU servers, then feed
  the artifacts into the science core (`../science/README.md`).

## Adding a new research program

1. Create a sibling folder of `tinygpt_formula/` with its own `README.md`
   following the same header structure (banner, badges, pipeline map).
2. Keep every path relative and every artifact inside the folder.
3. Register any testable claim in the science core's hypothesis registry
   (`../science/hypotheses/registry.yaml`) instead of inventing a private
   reporting format.
